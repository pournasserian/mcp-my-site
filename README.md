# mcp-my-site

Make your website answer AI agents. One command crawls a site and builds a search index; one small
web app serves that index through an [MCP](https://modelcontextprotocol.io) server and a search API.

- **Indexer** (`mcpmysite`): crawls the site from its sitemap (or a local folder of built HTML),
  extracts the main content as Markdown, chunks it by heading, embeds the chunks and writes an index.
- **Server** (`McpMySite.Server`): loads the index, exposes two read-only MCP tools (`search`, `fetch`)
  and an HTTP search endpoint for the site's own search box. Hybrid keyword + vector search, always.

One site per index and per server. Aimed at small sites, mostly under 1,000 pages. MIT licensed.

## Requirements

- .NET 10 SDK
- An OpenAI-compatible embeddings endpoint. The default is [OpenRouter](https://openrouter.ai) with
  `openai/text-embedding-3-small` at 512 dimensions. Set the key in the `OPENROUTER_API_KEY`
  environment variable; it is never written to a config file or the index.

## Quick start

```bash
# 1. Create a config file next to your site
dotnet run --project src/McpMySite.Indexer -- init https://example.com

# 2. Build the index (full rebuild every run; needs OPENROUTER_API_KEY)
dotnet run --project src/McpMySite.Indexer -- build

# 3. Try a query against the index without a server
dotnet run --project src/McpMySite.Indexer -- search "how do I reset my password"

# 4. Serve it
Index__Path=./index dotnet run --project src/McpMySite.Server
```

The server then answers at:

| Path | What |
|---|---|
| `/mcp` | MCP endpoint, streamable HTTP, stateless |
| `/api/search?q=...&limit=10` | JSON search results for a search box |
| `/healthz` | 200 with index details, 503 when no index is loaded |

Connect an MCP client to `https://your-host/mcp`. The server's instructions (a short outline of the
site) are generated by the indexer, so agents know what the site covers before they search.

## Indexer

### Config file: `mcpmysite.json`

`mcpmysite init <site-url>` writes this file with defaults. Every key is optional except `siteUrl`.
Paths are relative to the config file.

```jsonc
{
  "siteUrl": "https://example.com",
  "siteName": null,                   // defaults to og:site_name, then the host
  "source": {
    "type": "crawl",                  // "crawl" or "folder"
    "folder": null,                   // built HTML, when type is "folder"
    "folderUrlStyle": "clean"         // "clean": about.html -> /about; "file": keeps .html
  },
  "crawl": {
    "useSitemap": true,               // sitemap.xml and sitemap indexes, from robots.txt or /sitemap.xml
    "alwaysFollowLinks": false,       // links are followed anyway when there is no sitemap
    "respectRobotsTxt": true,         // robots.txt rules and noindex (meta and X-Robots-Tag)
    "maxPages": 1000,
    "include": [],                    // path globs, e.g. "/docs/**"; empty means everything
    "exclude": [],                    // e.g. "/tag/**"
    "concurrency": 4,
    "delayMilliseconds": 0,
    "timeoutSeconds": 30,
    "userAgent": "McpMySiteIndexer/0.1 (+https://github.com/pournasserian/mcp-my-site)"
  },
  "chunking": { "maxChars": 1500, "minChars": 200 },
  "embeddings": {
    "endpoint": "https://openrouter.ai/api/v1",   // any OpenAI-compatible base URL
    "model": "openai/text-embedding-3-small",
    "dimensions": 512,
    "apiKeyEnvironmentVariable": "OPENROUTER_API_KEY",
    "batchSize": 64
  },
  "cache": { "enabled": true, "path": ".mcpmysite/embedding-cache.sqlite" },
  "output": { "directory": "index", "store": "json" },   // "json" or "sqlite"
  "safety": {
    "minPages": 1,
    "maxPageDropPercent": 50,         // fail if the page count fell by more than this vs the previous index
    "maxErrorPercent": 20,            // fail if more pages than this errored
    "lowTextChars": 200               // pages with less extracted text are flagged in report.json
  },
  "instructionsPreamble": null        // text placed before the generated site outline
}
```

CLI overrides: `build --site-url`, `--folder`, `--output`, `--store`, `--max-pages`, `--verbose`.

### What the indexer does

1. Reads `robots.txt`, then the sitemap(s). Without a sitemap it follows links from the home page.
   Only HTML on the site's own host is fetched; `noindex` pages and robots-disallowed paths are skipped.
2. Picks the content automatically: `<main>` or `<article>` first, then a text-density heuristic.
   Navigation, headers, footers, asides, forms and scripts are removed. There are no selector
   overrides by design.
3. Stores each page as Markdown with title, description, language, headings and modified date.
   No HTML and no link graph are kept.
4. Splits pages into heading-aware chunks that carry the page title and heading path, embeds them
   (cache hits skip the provider) and writes the index.
5. Refuses to publish a broken build: fails when the page count drops sharply against the previous
   index in the output folder, or when too many fetches errored. Writes `report.json` either way.

### Index layout

Every index has a `manifest.json` with the format version, store type, site URL, embedding model
and dimensions, build time, page and chunk counts and the generated server instructions.

| Store | Files | Best for |
|---|---|---|
| `json` | `pages.json`, `chunks.json`, `vectors.bin` (raw float32) | up to a few hundred pages; loaded fully into memory |
| `sqlite` | `index.sqlite` (pages, chunks with vectors, FTS5 keyword index) | larger sites; vectors are still read into memory on load |

Both stores run keyword search (BM25 or FTS5), vector search (cosine) and reciprocal-rank fusion
themselves, and return one result per page with a highlighted snippet.

### Running in CI

Build the index in your site's deploy pipeline and publish the output folder to static hosting
(the site itself, blob storage, a CDN). The server can load it straight from that URL and swaps a new
index in without a redeploy.

## Server

Configuration lives in `appsettings.json`; secrets come from environment variables. Any setting can be
overridden with the `Section__Key` environment variable form.

| Setting | Default | Meaning |
|---|---|---|
| `Index:Path` | | Local index directory |
| `Index:Url` | | URL of `manifest.json` or the folder that holds it. Takes precedence over `Path` |
| `Index:PollIntervalSeconds` | 300 | How often to check for a new index; 0 disables polling |
| `Embeddings:Endpoint` | OpenRouter | OpenAI-compatible base URL for query embeddings |
| `Embeddings:ApiKeyEnvironmentVariable` | `OPENROUTER_API_KEY` | Where the key is read from |
| `Mcp:Path` | `/mcp` | MCP endpoint path |
| `Mcp:ApiKey` | | When set, MCP requests need `Authorization: Bearer <key>` or `X-Api-Key`. Set via `Mcp__ApiKey` |
| `Mcp:Instructions` | | Replaces the indexer-generated instructions |
| `Mcp:AllowedOrigins` | `[]` | Origins allowed to call the MCP endpoint from a browser |
| `SearchApi:Enabled` | true | |
| `SearchApi:Path` | `/api/search` | |
| `SearchApi:AllowedOrigins` | `[]` | Your site's origin(s), for the browser search box. No key |
| `SearchApi:MaxLimit` | 20 | |
| `RateLimiting:PermitPerMinute` | 60 | Per client IP, across MCP and search API |
| `RateLimiting:UseForwardedHeaders` | true | Trust `X-Forwarded-For` from the platform proxy. Set false when not behind one |
| `Telemetry:LogQueryText` | false | Include query text in logs and traces |
| `APPLICATIONINSIGHTS_CONNECTION_STRING` | | Sends traces, metrics and logs to Application Insights |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | | Used when no Application Insights connection string is set |

The query model and dimensions always come from the index manifest, so queries are embedded exactly
like the content was. If the embedding provider fails on a query, that request is answered from
keyword search and the fallback is recorded (`fallback` tag on the `mcpmysite.search.requests`
metric, `keywordOnly: true` in the response).

### MCP tools

- `search(query, limit)`: hybrid search, one result per page with title, URL, snippet, section and score.
- `fetch(url)`: the full page as Markdown with title, description, language and modified date.

Both are read-only and return structured content. There are no resources or prompts.

### Search API

```
GET /api/search?q=reset+password&limit=5
```

```json
{
  "query": "reset password",
  "keywordOnly": false,
  "results": [
    {
      "title": "Account settings",
      "url": "https://example.com/help/account",
      "description": "...",
      "snippet": "...plain text excerpt...",
      "highlightedSnippet": "...excerpt with <mark>reset</mark> <mark>password</mark>...",
      "section": ["Security"],
      "score": 0.0325
    }
  ]
}
```

### Deploy

The server is a plain container. `src/McpMySite.Server/Dockerfile` builds it; run from the repo root:

```bash
docker build -f src/McpMySite.Server/Dockerfile -t mcp-my-site .
docker run -p 8080:8080 -e Index__Url=https://example.com/index/ -e OPENROUTER_API_KEY=... mcp-my-site
```

The reference deployment is Azure App Service (Linux container). Set the same environment variables
as app settings, plus `APPLICATIONINSIGHTS_CONNECTION_STRING` for telemetry. Azure API Management in
front of it is optional.

## Development

```bash
dotnet build
dotnet test
```

Projects:

- `src/McpMySite.Core`: index model, manifest, stores (JSON, SQLite), hybrid search, embedding client.
- `src/McpMySite.Indexer`: the `mcpmysite` CLI.
- `src/McpMySite.Server`: ASP.NET Core app with the MCP server and search API.
- `tests/McpMySite.Tests`: unit and integration tests, including the web app booted in-process.

## Out of scope for V1

Admin UI, multi-site hosting, JavaScript rendering, PDFs, pages behind a login, a chat widget and
search-as-you-type. A chat API (OpenAI-compatible, Microsoft Agent Framework) is planned for V2.
